# Anthropic model discovery

When `ANTHROPIC_API_KEY` is set and the allowlist (`EAP_ALLOWED_MODELS`) contains `anthropic:*`, the platform asks Anthropic which models the key can use: `GET https://api.anthropic.com/v1/models?limit=1000` with the `x-api-key` and `anthropic-version` headers, following `after_id` while `has_more` is true, with a 5 s timeout per request. Only the ids Anthropic returns are offered (so a key without a Fable-class entitlement never sees one), and the result is cached like the other providers (5 minutes when it succeeded, 30 seconds when it failed). The API (`GET /models`, `/providers`, `/architect/options`) and the worker's Architect allowlist both do this. When the listing fails (401/403, timeout, HTTP error, malformed body), the provider shows `unreachable` with its error text and a small fallback set is offered instead: `claude-sonnet-5-5`, `claude-opus-5-5`, `claude-haiku-5-5`, marked `source: "fallback"` (discovered ids are `"discovered"`). The Architect's default model is the best-ranked allowed model; among Claude ids that is `claude-sonnet-5-5`, then `claude-opus-5-5`, `claude-haiku-5-5`, then the other sonnet/opus/haiku ids newest first, and Fable-class ids last (they need a separate entitlement).
